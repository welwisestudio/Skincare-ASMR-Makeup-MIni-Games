# YouTube Playables: JavaScript integration

Интеграция выполнена непосредственно в Phaser/JavaScript по локальным файлам `YouTubePlayablesSkill`. Unity, C#, `.jslib` и сторонние рекламные сети не используются.

## Запуск и облако

- Первый script в HTML загружает `https://www.youtube.com/game_api/v1`.
- `firstFrameReady()` вызывается из внешнего `playables-startup.js` после создания DOM загрузочного экрана, до запуска игры. Встроенного JavaScript в HTML нет: запуск работает при nonce CSP, запрещающей inline-скрипты. `gameReady()` — после загрузки облака, ресурсов и появления интерактивного меню.
- `loadData()` загружается до создания приложения. Пустая строка, пробельная строка, сериализованные `{}` и `null` означают отсутствие прогресса. Сохранения со `stars` без версии мигрируют как версия 1. Ошибка SDK, повреждённый JSON или неизвестная версия блокируют вход с кнопкой повтора; новый прогресс поверх старого не записывается. Ожидание загрузки ограничено 15 секундами. Ошибки облачного чтения и запуска приложения показываются отдельно; причина и тип ошибки SDK выводятся в консоль без содержимого сохранения. Отказ загрузки шрифта не блокирует игру.
- Все записи идут через `saveData()`. Очередь последовательная, промежуточные снимки объединяются, при ошибке сохраняется последний снимок в оперативной памяти и выполняется повтор через 5 секунд/после resume/по кнопке. Есть индикатор несохранённых данных. Ограничение размера проверяется до обращения к SDK.
- Сохранения выполняются при значимых изменениях: награда, покупка, завершение и запуск уровня, смена настроек, резервирование бонусного раунда, а также при `onPause`. Временной подарок сохраняется раз в 5 секунд.
- Нет localStorage, sessionStorage или IndexedDB для прогресса, нет локального резервного сохранения. Старые **облачные** версии 1–3 нормализуются существующими миграциями. Старое браузерное сохранение автоматически не импортируется.
- Вне Playables доступна только текущая сессия без постоянного сохранения; объявления недоступны и награды за них не имитируются.

## Реклама

Rewarded использует `requestRewardedAd(rewardId)`. Награда выдаётся только при `true`; `false`, исключение и отсутствие SDK не выдают ничего. Идентификаторы стабильны: `skincare-coins`, `skincare-result-x3`, `skincare-hint`, `skincare-skip`, `skincare-play-time-gift`, `skincare-level-chest`, `skincare-lucky-wheel`, `skincare-gift-box`, а также стабильные идентификаторы конкретных VIP, уровней, предметов и бонусных режимов. Демонстрационный рекламный экран удалён.

Interstitial подключён к запуску уровня из меню/Play, Next, Replay/Restart/Retry, повтору стадии через Try Again, возврату в меню и запуску/выходу бонусных игр. Первоначальное появление меню не вызывает рекламу. После получения rewarded, которая сама запускает уровень или бонус, дополнительный interstitial не запрашивается. Одновременно может выполняться только один рекламный запрос; повторные нажатия не запускают конкурирующие переходы.

**Ограничение публичного SDK v1:** `requestInterstitialAd()` возвращает `Promise<void>` и не подтверждает фактический показ. `onPause/onResume` относятся ко всем паузам и также не доказывают показ. Поэтому точное условие «сброс только после показа» реализовать достоверно невозможно без нового сигнала от YouTube.

В текущем билде применён консервативный вариант: между успешно завершёнными interstitial-запросами не менее **30 000 мс**, отсчёт от завершения предыдущего запроса. Ошибка/отсутствие API/отказ нашего ограничения не сбрасывают интервал. Успешный запрос без показа тоже может начать интервал — это известное отличие от желаемого условия. В коде поле специально называется `lastInterstitialRequestCompleted`, а не «время показа». Не используется эвристика по длительности или событиям паузы. Первый запрос в сессии доступен на первом подходящем переходе.

## Score, звук, пауза

- `sendScore({value})`: число уникальных уровней с сохранёнными звёздами, диапазон 0–58. Не сумма звёзд и не количество повторов. Пропущенные VIP без звёзд не учитываются. Отправка после загрузки и нового завершения; новые значения не отправляются, пока ожидает запись облачного прогресса. Повторные значения не дублируются. Ошибка отправки повторяется при следующем сохранении/resume.
- Глобальное состояние звука YouTube применяется сразу и через `onAudioEnabledChange`; внутриигровой переключатель не может отменить mute платформы.
- `onPause` останавливает игровой цикл, ввод, эффекты и звук и инициирует запись прогресса. Возобновление только через `onResume`, с сохранением пользовательской паузы/открытого окна. Браузерные focus/visibility-события не управляют паузой внутри YouTube; стандартные обработчики Phaser отключены для этой среды.
- Во время рекламы ввод и игровой цикл также блокируются. Результат рекламы не применяется до resume, если платформа поставила игру на паузу.
- Язык запрашивается через асинхронный `getLanguage()`, не хранится в прогрессе. Игра остаётся англоязычной. Health API вызывается без параметров.

## Проверки

`node scripts/playables-unit.mjs` — сериализация записей, ошибки и повторы, последний снимок, запись при паузе, размер, интервал 30 секунд на управляемых часах, параллельные запросы, true/false/reject, стабильные rewardId, score и no-op среда.

`node scripts/playables-browser.mjs` — браузерная интеграция с подменённым SDK: порядок загрузки, ошибки/повреждение облака, отказ локальных хранилищ, реальные кнопки переходов, Retry/Try Again/Next, rewarded, покупки, mute, пауза, сохранение и перезагрузка.

`node scripts/cloud-save-test.mjs` — пустые и старые сохранения, сохранение прогресса при миграции, запрет записи после неудачного чтения.

`node scripts/playables-production.mjs` — собранный билд, SDK как глобальная lexical-переменная, nonce CSP, отсутствие inline-скриптов и Page Visibility API, порядок firstFrameReady/loadData/gameReady, пустые и старые сохранения, ошибки SDK и повтор, запрет перезаписи повреждённых/неизвестных сохранений, отсутствие внешних ресурсов кроме SDK, облачная перезагрузка, покупка за rewarded, телефон/ПК и отсутствие dev-global.

Phaser импортируется из ESM-сборки. Vite удаляет стандартный обработчик автоматической паузы Phaser до обработки зависимостей; пакеты в `node_modules` не изменяются. Проверка production запрещает Page Visibility API и в коде движка, и в коде игры. Включённый SDK управляет паузой и рекламой также при локальном тестировании: отказ реального SDK никогда не превращается в тестовую награду.

Это автоматизированные проверки контрактов SDK, **не проверка реальной выдачи рекламы YouTube**. Перед публикацией нужно загрузить ZIP в Playables Developer Portal, включить monetization, пройти официальный SDK Test Suite и проверить реальные объявления и облачное продолжение на аккаунте YouTube, включая Android/iOS. Настройки портала из локального проекта изменить нельзя; загрузка в портал в рамках этой задачи не выполнялась.

Справочные первоисточники: [JavaScript SDK](https://developers.google.com/youtube/gaming/playables/reference/sdk), [Monetization](https://developers.google.com/youtube/gaming/playables/reference/monetization).
