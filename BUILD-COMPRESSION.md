# Сжатие билда без уменьшения разрешения

## Результат

| | До | После |
|---|---:|---:|
| ZIP для загрузки | 24 836 465 байт / 24,84 МБ | **13 948 910 байт / 13,95 МБ** |
| Распакованная сборка | 25 874 502 байта / 25,87 МБ | **14 990 162 байта / 14,99 МБ** |

ZIP уменьшился примерно на **44%**. Даже вся распакованная игра укладывается в 15 миллионов байт, без расчёта на HTTP-сжатие YouTube. Это 14,30 МиБ для распакованной игры. Полный начальный набор ресурсов не больше полного билда.

## Что сделано

- WebP перекодируется libwebp через Pillow, `method=6`, без изменения размеров. Базовое качество 82; шесть чувствительных текстур ткани/аксессуаров — 92, подушка — 88.
- Эффекты пудры и пены оставлены исходными: в них повторное сжатие сглаживало мелкую зернистость. Маленькие ассеты меньше 24 КиБ тоже не перекодируются. Всего 77 используемых изображений остаются исходными, 280 оптимизированы.
- Для всех 357 используемых изображений автоматически проверены исходные размеры и **побайтное совпадение альфа-канала**. Контуры прозрачности, маски, размеры объектов и координаты не менялись. Фон не ресайзился; масштаб canvas, DPR, сглаживание, шрифты и игровой код не менялись.
- Из сборки исключены 12 старых VIP-иллюстраций, отсутствующих в актуальном реестре загрузки `UI_ASSETS`. Их исходники остаются в `public`; действующие VIP-уровни используют другую графику.
- Если перекодирование увеличивает файл, остаётся исходник. Каждая сборка берёт входные данные из `public`, а не из уже сжатого `dist`: повторного накопления потерь нет. Кеш привязан к SHA-256 исходника, параметрам и версии кодека.

Это контролируемое сжатие с потерями RGB, **не математически lossless**. Разрешение и альфа сохраняются точно. Сравнены нативные фрагменты при 100% и игровые экраны на телефоне/ПК; в игровом масштабе заметного ухудшения не обнаружено. Численные метрики служат проверкой, но не гарантией субъективной неразличимости.

## Почему не просто ZIP / другой формат

24,3 МБ исходного билда приходились на WebP. Повторное gzip-сжатие всех этих изображений давало всего около 12 КБ экономии. Варианты WebP 92 и 88 оказались слишком большими; выбран адаптивный профиль с более высоким качеством для чувствительных изображений. ZIP остаётся обычным ZIP — отдельный распаковщик в игре не нужен. Формат WebP сохранён, новые декодеры, внешние ресурсы и требования к поддержке AVIF не добавлялись.

Использованы документированные возможности [libwebp](https://developers.google.com/speed/webp/docs/cwebp). YouTube также учитывает HTTP-сжатие при измерении начального бандла, но результат здесь достигнут до него: [официальный FAQ](https://developers.google.com/youtube/gaming/playables/support/certification_faq).

## Сборка и откат

Оптимизированный билд и ZIP:

```powershell
npm run package
```

Откат к исходной графике с пересборкой ZIP:

```powershell
npm run package:original
```

Только папка `dist`: `npm run build` / `npm run build:original`.

Откат проверен: `build:original` восстановил все 381 файла предыдущего билда **побайтно**. SHA-256 всех исходников `public` также совпал со снимком до работы. После проверки снова собран оптимизированный вариант.

Готовая резервная копия до оптимизации: [Skincare-ASMR-before-compression.zip](reference/build-compression/Skincare-ASMR-before-compression.zip). Исходные `package.json` и `vite.config.js` сохранены рядом с суффиксом `.original`. Чтобы полностью отключить оптимизацию в обычном `build`, достаточно вернуть команду `vite build`; код игры менять не требуется.

Профиль: `scripts/compression-profile.json`. Обработчик: `scripts/optimize-build.py`. Нужны Python, Pillow и Node.js. Если дальнейшие изменения увеличат билд свыше 15 000 000 байт, сборка остановится с отчётом, а не молча ухудшит качество.

## Проверки и сравнения

- Все 58 уровней открыты с исходной и оптимизированной графикой в 390×844 и 1703×820 при DPR 2; ошибок загрузки и JavaScript не было.
- Пройдена проверка готового Playables-билда с CSP: облачные сохранения, rewarded, покупка, interstitial и перезагрузка. Она использует имитацию SDK, не реальные показы YouTube.
- ZIP сверяется побайтно с `dist` скриптом `scripts/verify-package.py`.
- Отчёт по каждому файлу, размерам, альфе и хешам: `test-results/build-compression/report.json`.
- Нативные PSNR/SSIM и самые чувствительные фрагменты: `test-results/build-compression/quality.json`, `compare-*.png`. Метрика SSIM использует яркость, окно 7×7 и только видимые пиксели; это не показатель «процента сохранённого качества».
